# AI 编程助手 — 设计文档（Design Doc）

> 面向代码仓库开发场景的智能 Agent，参考 Claude Code 的交互与执行机制。
> 定位：个人项目

## 1. 总体架构（三层）

```
┌─────────────────────────────────────────────────────────────┐
│                        服务层 (Service)                       │
│   会话管理 Session · 配置 Config · 持久化 Persistence          │
│   （管理 Agent 的生命周期、用户配置、数据落盘）                   │
└──────────────────────────┬──────────────────────────────────┘
                           │ 组装并注入
┌──────────────────────────▼──────────────────────────────────┐
│                        引擎层 (Engine)                        │
│   Agent 编排 · Query Loop · 上下文管理 · 记忆调度 · 终止判断     │
│   （只面向 LLM 客户端抽象 + 工具注册表抽象，不依赖具体实现）       │
└──────────────┬──────────────────────────┬───────────────────┘
               │ 调用 LLMClient 抽象        │ 通过 ToolRegistry 调用
┌──────────────▼─────────────┐   ┌─────────▼───────────────────┐
│   LLM 客户端 (llm/)         │   │        工具层 (tools/)        │
│  OpenAIClient / MockClient │   │ 注册表 · 执行器 · 内置工具      │
└────────────────────────────┘   │ list_files/read_file/grep/    │
                                 │ write_file · 副作用区分 · 并发  │
                                 └──────────────────────────────┘
```

引擎层只 import 三个抽象——`LLMClient`（模型交互）、`ToolRegistry`（工具集）、`MemoryManager`（记忆）。具体工具在 `service` 层组装时 `register` 进注册表，引擎对"有哪些工具"零硬编码。这样：

- 新增工具 = 写一个 `BaseTool` 子类 + 一行 `registry.register(...)`，引擎不动。
- 换模型 = 换 `LLMClient` 实现，引擎不动。
- 测试 = 注入 `MockLLMClient` 即可离线跑通整条链路。

## 2. 核心流程：ReAct Query Loop

```
用户输入
   │
   ▼
┌────────────────────────────────────────────────────┐
│ for step in 1..max_steps:                          │
│   1. 构建上下文 context = hot 记忆 + system prompt   │
│   2. 模型推理  response = llm.chat(context, tools)  │
│   3. 解析：最终答案 or 工具调用？                      │
│      ├─ 无 tool_call → 终止，返回 final_answer       │
│      └─ 有 tool_call ─┐                            │
│   4. 工具执行（见 §4 并发策略）                       │
│   5. 结果回填 observation 追加进上下文/记忆           │
│   6. 终止判断：显式 finish / 达到 max_steps / 异常     │
│      └─ 未终止 → 回到 2                             │
└────────────────────────────────────────────────────┘
   │
   ▼
最终答案 + 执行轨迹（steps）
```

**时序（一轮工具调用）**：

```
Agent            LLMClient         ToolExecutor        Memory
  │ build_context    │                  │                  │
  ├─────────────────►│ chat(messages)   │                  │
  │◄─────────────────┤ response{tool_calls}               │
  │ parse            │                  │                  │
  ├────────────────────────────────────►│ execute(calls)   │
  │                                    │─(read 并行)──►    │
  │                                    │─(write 串行)─►   │
  │◄───────────────────────────────────┤ results          │
  ├── append observation ─────────────────────────────────►│
  │   (回填)          │                  │                  │
```

**终止判断**：

1. **显式终止**：模型返回无 tool_call 的纯文本 → 视为最终答案。
2. **步数上限**：超过 `max_steps`（默认 10）→ 强制用最后一轮上下文让模型收尾，防止死循环/烧 token。
3. **连续无进展检测**：连续 N 轮执行相同工具且结果无变化 → 判定卡死，提示模型换策略。
4. **异常兜底**：工具抛异常被捕获为 `ToolResult(error=...)` 回填给模型，而非中断整个循环（让模型看到错误并自我修正）。
